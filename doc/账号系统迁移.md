# 账号系统迁移

系统账号现以 `data/codebuddy2api.sqlite3` 中的 `system_users` 表为唯一运行时权威。旧版 `secrets/users.txt` 只在账号系统尚未初始化时读取一次；迁移成功后，登录、改密和账号管理都不再读取该文件。

## 升级前准备

1. 停止服务，完整备份 `data`、`secrets` 和 `.env`。
2. 确认旧 `users.txt` 仍在 `CODEBUDDY_USERS_FILE` 指向的位置。Docker 部署默认是 `secrets/users.txt`。
3. 不要先删除旧文件，也不要手工修改 SQLite schema。

账号 schema 升级到 v5 后，旧版本程序不能直接继续使用该数据库。需要回滚时，应停止新版并恢复升级前的完整备份。

## 首次启动时会发生什么

### 既有安装且保留了旧用户文件

服务会先完整校验文件，再把全部账号和认证初始化状态放在同一个 SQLite 事务中提交。迁移后的账号不要求首次改密，原密码保持有效。

旧文件必须满足以下条件：

- 是 UTF-8 编码的普通文件，不能是符号链接或多硬链接文件；
- 每条非空、非注释记录都是 `用户名:PBKDF2哈希`；
- 哈希必须是项目支持的规范 PBKDF2-SHA256 格式；
- 重复用户名以文件中的最后一条记录为准。

权限宽于 `0600` 时服务会告警但仍可迁移；任何内容或文件形态错误都会使整个迁移失败，不会留下部分账号。

迁移成功后再次启动时，旧文件只会触发“已忽略”的 WARNING。确认所有账号都能登录后即可删除 `secrets/users.txt`；`CODEBUDDY_USERS_FILE` 也可从 `.env` 移除。

### 既有安装但旧用户文件已丢失

服务会拒绝启动，不会用公开的 `admin/admin` 覆盖既有安装。使用同一运行数据目录执行：

```bash
venv/bin/python3 scripts/manage_users.py set-user admin
```

Docker Compose 部署使用：

```bash
docker compose run --rm codebuddy2api set-user admin
```

命令会隐藏输入新密码两次，并直接建立正式 SQLite 账号。也可显式传入 `--password`，但明文可能出现在 shell 历史或进程参数中。

### 真正的全新安装

没有旧用户文件、既有 schema、用户数据或凭证时，服务默认创建一次性引导账号：

- 用户名：`admin`
- 密码：`admin`
- 有效期：本次服务启动后的 1 小时

启动日志会明确显示它正在使用“内置默认密码”。登录后只能访问改密页面、会话/改密/退出接口、前端静态资源和健康检查；必须先设置 8 至 128 个字符且不含 Unicode 控制字符的新密码。

可在首次启动前配置自定义初始值：

```dotenv
CODEBUDDY_BOOTSTRAP_USERNAME=admin
CODEBUDDY_BOOTSTRAP_PASSWORD=仅用于首次登录的初始密码
```

显式配置密码后，启动日志会标明它是“自定义初始密码”。无论使用哪一种初始密码，都必须首次改密，且引导账号超过 1 小时后需要重启服务才能重新获得一小时窗口。

若不允许自动创建引导账号，可设置：

```dotenv
CODEBUDDY_BOOTSTRAP_ENABLED=false
```

然后在启动服务前用 `manage_users.py set-user` 创建正式账号。账号一旦正式初始化，上述引导配置永久不再覆盖或校验 SQLite 账号。

## 日常账号管理

本地或 Release 安装：

```bash
# 新增账号或重置密码；add-user 是完全等价的别名
venv/bin/python3 scripts/manage_users.py set-user <用户名>

# 列出账号
venv/bin/python3 scripts/manage_users.py list-users
venv/bin/python3 scripts/manage_users.py list-users --json

# 删除账号认证记录
venv/bin/python3 scripts/manage_users.py delete-user <用户名>
venv/bin/python3 scripts/manage_users.py delete-user <用户名> --yes
```

Docker Compose：

```bash
docker compose run --rm codebuddy2api set-user <用户名>
docker compose run --rm codebuddy2api list-users
docker compose run --rm codebuddy2api delete-user <用户名>
```

这些命令直接操作共享 SQLite，运行中的服务无需重启。新增或重置密码会推进账号认证代次，使该账号已有的所有管理台会话失效；已有 API Key 不受影响。

不能删除最后一个系统账号。删除其他账号只移除认证记录，其 API Key、凭证、设置和统计数据会保留但不可使用；以后重建完全相同的用户名时，这些数据会重新可用。

旧的 `scripts/hash_password.py` 已停用，只会输出迁移指引并以状态码 1 退出。

## 管理台内修改自身密码

正式账号可进入“设置 → 账号安全”修改自身密码。需要输入当前密码、新密码和确认密码。修改成功后：

- 当前账号的全部管理台会话都会退出；
- 登录页会预填用户名并提示使用新密码重新登录；
- API Key、CodeBuddy 凭证、设置和统计数据保持不变。

如果网络在提交期间中断，管理台不会自动重试，因为无法确定服务端是否已经提交；请分别尝试新旧密码确认结果。
