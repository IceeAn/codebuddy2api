# 分词与本地计数

系统使用固定版本的官方分词数据离线计数，不访问 CodeBuddy、不选择或轮换凭证、不写入用量统计。结果供上下文预算参考，不等于 CodeBuddy 实际输入用量或账单。网关无法确认上游私有提示词、模板版本和多模态处理，因此即使使用官方模板也不承诺与上游数字完全一致。

## 获取与部署

Git 只保存 `src/tokenizer_catalog.json` 的来源仓库、固定 commit、文件大小、SHA-256、许可证，以及内置编码器代码。大词表位于被 Git 忽略的 `src/tokenizer_assets/blobs/`，相同内容去重保存。

开发环境安装依赖后手动执行一次：

```bash
python3 scripts/download_tokenizers.py
# 校验本地文件，不联网
python3 scripts/download_tokenizers.py --verify-only
# 使用已经下载的内容摘要缓存
python3 scripts/download_tokenizers.py --cache-dir /path/to/blobs
```

脚本仅下载清单指定的数据和许可证，不下载权重，也不执行模型仓库的 Python。内容不匹配即失败；所有文件下载、校验成功后才原子替换资源目录。更新锁定清单后需再次执行。启动时资源缺失或损坏会明确失败。

CI、Docker 和 Release 发布流程下载并打包资源；Docker 镜像及 Release 包部署后无需访问 Hugging Face。手工构建 Release 包之前也必须执行下载脚本。词表随 `src` 目录一起升级，用户资源存放在数据目录中，升级和回滚不覆盖用户资源。

ARMv7 上 tiktoken 可能需要从源码编译，手工安装 Python 依赖时需提供 Rust 和 C 编译器；Docker 的编译器仅存在于构建阶段。

## 默认模型

内置匹配使用真实模型 ID；不会猜测相近模型或把供应商别名自动映射到其他词表。具体来源、完整 commit 和每个文件的许可证见 [资源清单](../src/tokenizer_catalog.json)，设置页也提供固定版本的官方仓库链接。

- DeepSeek：`deepseek-v4-pro`、`deepseek-v4-flash`、`deepseek-v4.1-flash`。
- MiniMax：`minimax-m2.5`、`minimax-m2.7`、`minimax-m3`。
- GLM：`glm-5.2`、`glm-5.3`、`glm-5.3-flash`、`glm-5.1`、`glm-4.7`、`glm-4.6`、`glm-4.6v`。
- Kimi：`kimi-k3`、`kimi-k2.6`、`kimi-k2.5`。
- Hunyuan：`hy3`、`hy4-preview`。

以下 ID 尚无已确认的官方精确对应资源，默认返回 404，需要用户自行配置：`deepseek-v3-2-volc`、`glm-5.0`、`glm-5.0-turbo`、`glm-5v-turbo`、`kimi-k2.7`。支持视觉模型的文本计数不代表支持视觉输入计数。

## API

纯文本使用 `POST /tokenizer/v1/count_tokens`，接受 API Key Bearer：

```json
{"model":"glm-5.2","text":"你好，世界！"}
```

Anthropic Messages 使用 `POST /anthropic/v1/messages/count_tokens`，接受 `x-api-key` 或 Bearer，以及 `anthropic-version: 2023-06-01`：

```json
{"model":"glm-5.2","system":"请用中文回答。","messages":[{"role":"user","content":"你好"}]}
```

无需 `max_tokens`。消息、system、工具定义/结果和 thinking 等复用 Messages 协议转换及用户请求策略；系统提示词改写和强制思考策略也会影响计数。合成前缀 `anthropic/codebuddy/` 与模型命名空间处理规则同聊天接口。仅支持文本内容（含文本 document）；图片、音视频、PDF 和文件引用明确拒绝，不按字符数伪造多模态 token。

计数按协议转换及请求策略生效后的思考模式渲染。例如 Anthropic `adaptive` 按现有兼容规则转换为 `enabled`；强制思考模型仍优先使用强制策略。`thinking.clear_thinking=false` 会将历史推理保留选项传入支持它的模板，各模板使用其规定的参数名称。

成功响应均为：

```json
{"input_tokens": 8}
```

响应头说明计算方式：

| 响应头 | 取值 |
| --- | --- |
| `X-Tokenizer-Method` | `text`：纯文本词表计数；`template`：模板/内置消息编码器；`budget_v1`：无模板预算估算 |
| `X-Tokenizer-Source` | `builtin` 或 `user` |
| `X-Tokenizer-Revision` | 数据文件及编码配置的 SHA-256 |

`budget_v1` 仅用于未上传模板且未选择专用编码器的用户资源：对转换后 `messages` 和非空 `tools` 组成的对象，使用键排序、紧凑分隔符、保留 Unicode 的 JSON 字符串运行真实分词。它不模拟角色分隔符等模型模板开销。已存在但无效或不支持当前输入的模板直接失败，不回退。

管理台“API 测试 → Tokenizer”提供纯文本及完整 Anthropic JSON 测试。对应 `/api/admin/playground/tokenizer/v1/count_tokens`、`/api/admin/playground/anthropic/v1/messages/count_tokens` 只接受会话 Cookie，外部 API Key 无法使用；这些测试入口不出现在 OpenAPI 中。

## 用户资源与模型映射

在“设置 → Tokenizer”上传一组文件：

- Hugging Face：`tokenizer.json`；可附带 `tokenizer_config.json`、`chat_template.jinja`、`special_tokens_map.json`、`added_tokens.json`。
- Kimi：`tiktoken.model` 和 `tokenizer_config.json`，选择 Kimi 格式；K2 消息计数还需要官方聊天模板并选择 `kimi_k2`，K3 选择 `kimi_k3`。
- 可附带 `LICENSE`、`LICENSE-MODEL`。不接受 Python、压缩包、权重、任意文件名或重复文件。

消息编码器 `auto` 使用上传的 Jinja 模板，没有模板时使用上述预算算法；`jinja` 强制要求模板。DeepSeek、Kimi、HY 专用选项只能配合同系列对应官方词表使用，不能把选择编码器当作模型兼容性验证。多模板配置需选择模板名（存在 `default` 时默认使用它）。

上传资源在隔离进程中验证后保存。模板使用受限 Jinja 环境，不允许访问 Python 对象内部或修改共享数据；计数进程有并发、执行时间和内存限制，超限会终止并重建该进程。每个系统用户的文件、映射和资源缓存独立。

内置默认映射随系统升级。需要固定版本时点击“创建快照”，再将模型 ID 映射到这份用户资源；快照复制数据及编码配置，不会被后续内置数据升级覆盖。若官方资源更新，页面仅提示有更新，需要显式创建新快照、保存新映射后生效。快照固定数据，不冻结应用内编码器代码。删除用户映射后恢复当前内置默认；被映射引用的资源不能删除。

上传、创建快照和删除资源即时保存；映射编辑需点击“保存映射”。切换页面、设置 Tab 或刷新前会提示未保存编辑。

## 启动环境变量

全部为严格正整数，只从启动配置读取，用户数据库设置不能覆盖。MiB = 1048576 字节。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `CODEBUDDY_TOKENIZER_UPLOAD_MAX_BYTES` | `67108864` | 上传接口独立请求体上限，默认 64 MiB，包含 multipart 开销；同时限制资源文件总量 |
| `CODEBUDDY_TOKENIZER_WORKERS` | `2` | 全局分词工作进程数量 |
| `CODEBUDDY_TOKENIZER_TIMEOUT_SECONDS` | `30` | 单次进程任务截止时间（含传输、解析、模板及分词） |
| `CODEBUDDY_TOKENIZER_QUEUE_TIMEOUT_SECONDS` | `30` | 等待工作容量的最长时间，超时返回 429 |
| `CODEBUDDY_TOKENIZER_MEMORY_MAX_BYTES` | `805306368` | 每个工作进程内存上限，默认 768 MiB；Linux 限制地址空间，其他平台监测 RSS |
| `CODEBUDDY_TOKENIZER_RENDER_MAX_BYTES` | `33554432` | 模板输出上限，默认 32 MiB |
| `CODEBUDDY_TOKENIZER_CACHE_SIZE` | `2` | 每个工作进程最多缓存的分词引擎数 |
| `CODEBUDDY_TOKENIZER_MAX_MAPPINGS` | `512` | 每个用户最多保存的模型覆盖映射数 |

上传接口 `POST /api/admin/tokenizers/resources` 使用独立上限；其他接口继续遵守原请求体限制。反向代理也需要允许对应请求体大小及排队、执行所需时间。调整工作进程数量时需一起考虑内存预算。
