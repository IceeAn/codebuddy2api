# 公网部署与安全配置

## 支持范围

本指南面向受信任团队的单 worker 部署：浏览器和 API 客户端经 HTTPS 反向代理访问，后端端口不直接暴露到公网。正常部署不要求额外的代理登录或 IP 白名单；仍须使用应用账号或 API Key。它不是开放注册或互不信任多租户方案；如需此类部署，请先完成独立的身份、权限、配额和故障隔离设计。

## 1. 先初始化正式账号

本地/Release 安装在首次启动及开放代理之前执行：

```bash
venv/bin/python3 scripts/manage_users.py set-user admin
```

CLI 隐藏输入两次密码。不要使用公开默认密码，也不要把生产密码通过 `--password` 留在进程参数或命令历史。Docker 安装使用同一个持久卷执行：

```bash
docker compose run --rm codebuddy2api set-user admin
```

Compose 的 `run` 不发布服务端口。账号创建后设置 `CODEBUDDY_BOOTSTRAP_ENABLED=false`；确认数据持久化，不能通过丢弃数据库重新引导。账号 CLI 使用的目录必须与后续服务一致。不要修改 Compose 的 `user` 或使用 `--user` 绕过入口脚本的挂载准备与降权。

## 2. 配置固定公网来源

复制 `.env.example` 为应用根目录的 `.env`，至少设置以下项目。示例中 Nginx 与非容器后端在同一宿主；将域名替换为实际值：

```dotenv
CODEBUDDY_BOOTSTRAP_ENABLED=false
CODEBUDDY_HOST=127.0.0.1
CODEBUDDY_PORT=8001
CODEBUDDY_PUBLIC_ORIGIN=https://api.example.com
CODEBUDDY_ALLOWED_HOSTS=api.example.com
FORWARDED_ALLOW_IPS=127.0.0.1
CODEBUDDY_SSL_VERIFY=true
CODEBUDDY_MAX_CONCURRENT_REQUESTS=64
CODEBUDDY_MAX_REQUEST_BODY_BYTES=16777216
CODEBUDDY_REQUEST_BODY_TIMEOUT_SECONDS=30
CODEBUDDY_UPSTREAM_TIMEOUT_SECONDS=1800
CODEBUDDY_MAX_SSE_LINE_BYTES=1048576
CODEBUDDY_MAX_UPSTREAM_RESPONSE_BYTES=33554432
CODEBUDDY_MAX_UPSTREAM_ERROR_BYTES=65536
CODEBUDDY_ALLOWED_ORIGINS=
```

`PUBLIC_ORIGIN` 必须是 HTTPS 来源（包含非默认端口时需写出端口），不是带路径的 URL。启用后，Host 缺失/含通配符、关闭上游 TLS、无限并发及不明确的代理地址会使启动失败。Cookie 强制 Secure；来源校验不依赖客户可伪造的转发头。多条安全配置均为启动级配置，用户管理台设置不能覆盖。

`FORWARDED_ALLOW_IPS` 必须匹配**后端实际看到的代理连接 IP/CIDR**。Docker NAT 下可能是网桥网关，不能照抄 `127.0.0.1`，也不能设 `*` 或整个不可信网络。代理必须覆盖客户端传入的转发头，否则攻击者可能伪造限流 IP。公网 Origin 校验不能替代正确的代理信任设置。

64 并发与 32 MiB 响应上限是起始配置，不是资源容量保证。非流式聚合、JSON 解码和工具缓冲会有额外内存开销；按机器内存、模型输出和可信用户数压测后调整，特别是内存较小的设备。达到上限会拒绝请求或中止流，而不是无限排队。

## 3. HTTPS 反向代理

以下配置放在 Nginx 的 `http` 上下文内（通常是 `conf.d` 的文件）。使用有效证书并替换证书路径；DNS 应指向该代理。代理不缓存管理台或 API 响应，不重试已提交的生成请求：

```nginx
limit_conn_zone $binary_remote_addr zone=codebuddy_clients:10m;

server {
    listen 80;
    server_name api.example.com;
    return 308 https://api.example.com$request_uri;
}

server {
    listen 443 ssl;
    server_name api.example.com;
    ssl_certificate /etc/nginx/tls/fullchain.pem;
    ssl_certificate_key /etc/nginx/tls/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    if ($host != api.example.com) { return 444; }

    add_header Strict-Transport-Security "max-age=31536000" always;
    client_header_timeout 10s;
    client_body_timeout 10s;
    client_max_body_size 16m;
    send_timeout 30s;
    keepalive_timeout 30s;
    limit_conn codebuddy_clients 32;
    limit_conn_status 429;

    # 普通代理访问日志包含 URL；OAuth 参数不应进入日志。
    access_log off;

    location / {
        proxy_pass http://127.0.0.1:8001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Host "";
        proxy_set_header Forwarded "";
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_cache off;
        proxy_next_upstream off;
        proxy_connect_timeout 10s;
        proxy_send_timeout 30s;
        proxy_read_timeout 310s;
    }
}
```

`proxy_read_timeout` 是两次读取之间的空闲期限，不是总时长；应用另有 1800 秒总期限。代理的连接限制按 IP 生效，共用 NAT 的团队可能需要调整。代理自行产生的 413/429/超时错误不保证使用 OpenAI/Anthropic JSON 格式。多层代理应逐跳设计可信链，不直接使用任意客户端传入的 `X-Forwarded-For`。

先执行 `nginx -t`，再按系统服务管理方式加载配置。确认 HTTPS 和证书链正常后再让团队使用；HSTS 只应在 HTTPS 已稳定可用时启用。

### Docker 注意事项

仓库 Compose 默认将后端发布到 `127.0.0.1:8001`，适合宿主反向代理，并启用 `no-new-privileges` 限制后续 exec 提权（不妨碍入口以 root 准备目录后主动降权）。若代理也在容器中，使用隔离的 Docker 网络连接后端，仅发布代理的 80/443，移除后端端口发布；后端信任地址应是该专用网络中的代理地址或受控网段。不得把所有业务容器所在网段一律视为可信代理。操作系统防火墙与云安全组也应关闭后端 8001 端口。

数据目录包含可用的 CodeBuddy 凭证；只授予服务账号与必要运维读取权限。数据库/凭证文件权限为 0600 不等于加密，备份、宿主和 Docker 管理权限同样需要保护。不要将真实 `.env`、数据卷或备份加入镜像及 Git。

## 4. 浏览器与 API 契约

- 管理台写操作要求与配置来源一致的 Origin；无 Origin 时仅接受同源 Referer，二者都缺失、`null`、同站不同端口均拒绝。自动化脚本操作 Cookie 管理 API 时也必须提供正确来源；Origin 校验不是新的身份凭证，仍需要有效会话。
- `/api/admin/playground/*` 必须使用 `application/json`。`CODEBUDDY_ALLOWED_ORIGINS` 只控制 `/openai/*` 与 `/anthropic/*` 的跨域调用，不放行管理台。
- 外部协议只接受 API Key，不要求浏览器来源；管理 playground、`/docs`、`/redoc` 和 `/openapi.json` 只接受管理会话。不能混用两种认证方式。
- 文档脚本随前端构建同源发布，源码安装须先构建前端；Release 与镜像已经包含构建结果。无需开放 CDN 或恢复 `unsafe-inline` 脚本策略。
- 422 校验错误不再回显原始输入或 Pydantic context；错误文本受控且限长。不得依赖上游任意原始错误体进行程序控制。

## 5. 上线验收与持续检查

1. 正式账号可登录；`admin/admin` 不可登录；会话包含 HttpOnly、Secure、SameSite；响应包含 CSP、DENY、防嗅探头，私有数据为 `private, no-store`。
2. 互联网无法直连 8001；未知 Host 拒绝；伪造 `X-Forwarded-For` 不能变更有效限流来源；非可信连接的转发头不改变后端判断。
3. 同源登录、改密、凭证操作及 playground 正常；同站异源页面触发的 POST 为 403；text/plain playground 为 415；允许的外部 API 跨域不扩大到管理 API。
4. `/docs` 与 `/redoc` 在登录后正常渲染，未登录返回认证错误；浏览器不请求第三方脚本/字体。退出或密码改变后旧会话不能访问文档或 schema。
5. 使用模拟上游验证超大单行/错误体、持续心跳、首块及总期限、客户端取消和慢接收；超限后连接、任务及并发名额能回收。不要用真实凭证进行破坏性负载测试。
6. CI 的双 Python 版本、前端格式/lint/构建/覆盖率与 Chromium 回归通过；运行依赖及前端依赖审计无未处置报告；发布仍执行三架构镜像扫描与 digest 签名。发布前复查当时的审计结果，不使用本轮结果代替未来检查。

HTTPX/HTTPCore 调试日志被禁用，应用异常不保留原始 traceback；排障依赖受控错误类型、状态及本地测试。不要为了排障在公网恢复完整请求/响应日志。依赖安全建议参见 [OWASP CSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) 与 [Uvicorn 代理配置](https://www.uvicorn.org/settings/#http)。
