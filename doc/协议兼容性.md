# OpenAI 与 Anthropic 协议兼容性及多模态验证

本文区分网关实现保证与 CodeBuddy 上游模型能力。字段被接受、HTTP 200 或 SDK 能解析，均不能单独证明模型支持该能力。

## 接口与支持范围

外部入口为 `POST /openai/v1/chat/completions`，使用管理台生成的 Bearer API Key；管理台入口为 `POST /api/admin/playground/openai/v1/chat/completions`，仅接受会话 Cookie。两者共享转换逻辑，管理台页面仍只提供文本输入。

| 能力 | 网关行为 | 上游验证状态 |
| --- | --- | --- |
| 文本、思考、function 工具及工具历史 | 保留请求，流式输出或非流式聚合 | 已有真实验证与回归测试 |
| 图片 URL、Base64 data URL、多图、图文交错 | 保留内容块顺序、URL 和 detail；不下载、转码或保存图片 | 本次 Kimi 多图识别成功 |
| `developer`、扩展消息字段 | 保留并交给上游处理 | 不保证各模型的角色优先级 |
| 音频输入、file 内容块、file_id | 校验已知字段结构后透传；不提供 Files API | 本次端点明确拒绝 input_audio 和 file |
| 音频输出 | 请求透传；流式保留音频字段，非流式合并音频字节、转录和元数据 | 转换通过合成测试；本次上游未生成音频 |
| JSON mode、JSON Schema、strict | 原样透传 | 本次样本未遵守输出格式，不承诺约束生成 |
| refusal、annotations、logprobs | 流式保留，非流式聚合；不伪造缺失信息 | 转换有合成测试；本次 logprobs 未返回有效值 |
| 旧 function_call、custom 工具 | 保留消息；聚合参数或 input，沿用工具 ID 和上游 index | 转换有合成测试，未作真实上游承诺 |
| 未知请求字段及内容类型 | 保留给上游判断 | 不进行能力白名单拦截 |
| 未知响应字段 | 流式保留；非流式仅保证本文列出的字段 | 不猜测未知分片的合并方式 |
| `n > 1` | 本轮保留既有行为 | 非流式仅聚合首个 choice；流式可能重复其他 choice，请使用单候选 |

图片生成、视频、文件上传和已存储 completion 的查询／修改／删除不在此接口实现范围。媒体不进入统计存储；统计继续仅保存脱敏指标。默认请求体上限为 16 MiB，Base64 编码后的整个 JSON 计入限制，可由 `CODEBUDDY_MAX_REQUEST_BODY_BYTES` 调整。

## 参数及返回约定

- `max_completion_tokens` 映射为上游 `max_tokens`。两个字段均为非空时必须相同，否则返回 400；仅允许非布尔正整数，`null` 按未指定处理。上游实际截断、思考 token 和 usage 计数可能有偏差，不能视为精确额度控制。
- 原有模型默认值、命名空间剥离、强制思考和温度策略保持有效。聊天路径不查询模型能力，也不会自动换模型。
- 上游始终使用 SSE，并强制请求 usage；客户端非流式请求由网关增量聚合。内部统计始终观察原始 usage。
- 客户端仅在 `stream_options.include_usage=true` 时收到末尾 `choices: []` 的 usage 块；普通块的 usage 为 null。未启用时不发送 usage。上游缺失 usage 时不补零，异常终止不伪装为成功完成。
- 混合 reasoning/content 拆为依次到达的分块，首个 assistant 角色只补一次，合成分块不重复携带首个 choice 的 logprobs 或 usage。正常流以 `[DONE]` 结束。
- 非流式分别拼接文本、思考、拒绝、工具参数和转录；工具按 index 排序。概率和引用按到达顺序合并；usage 保留上游完整明细，不累加累计统计。音频 data 分块必须是有效 Base64，解码后的字节合并后重新编码，不拼接带 padding 的 Base64 字符串。无文本的工具／拒绝／音频响应返回 content 为 null；明确提供的空字符串保持为空字符串。
- OpenAI 命名空间中的错误统一为 `{"error":{"message":"...","type":"...","param":null,"code":null}}`。本地字段错误提供 param；保留 HTTP 状态、Retry-After 和必要鉴权头。CodeBuddy JSON 错误提取 message／msg 和 code，不将整个 JSON 错误体当作 message。内部异常不回显异常详情。

## 图片调用示例

以下使用实际模型 ID `kimi-k3-1`，不是根据模型列表自动选择的别名。图片能力仍取决于当前账号和上游模型。

```python
import base64
import os
from pathlib import Path

from openai import OpenAI

client = OpenAI(
    api_key=os.environ["CODEBUDDY_API_KEY"],
    base_url="http://127.0.0.1:8001/openai/v1",
)
image = base64.b64encode(Path("测试图片.png").read_bytes()).decode("ascii")
messages = [{"role": "user", "content": [
    {"type": "text", "text": "依次描述两张图片。"},
    {"type": "image_url", "image_url": {
        "url": "data:image/png;base64," + image, "detail": "high",
    }},
    {"type": "image_url", "image_url": {
        "url": "https://dummyimage.com/128x64/00ff00/00ff00.png", "detail": "auto",
    }},
]}]
result = client.chat.completions.create(
    model="kimi-k3-1", messages=messages, max_completion_tokens=512,
)
print(result.choices[0].message.content)

stream = client.chat.completions.create(
    model="kimi-k3-1", messages=messages, max_completion_tokens=512,
    stream=True, stream_options={"include_usage": True},
)
for part in stream:
    if part.choices:
        print(part.choices[0].delta.content or "", end="")
    if part.usage is not None:
        print(part.usage)
```

## Anthropic Messages 兼容范围

外部入口为 `POST /anthropic/v1/messages`，接受 `x-api-key` 或 Bearer API Key；同时提供时两者必须一致。管理台入口为 `POST /api/admin/playground/anthropic/v1/messages`，仅以会话 Cookie 鉴权。请求必须带 `anthropic-version: 2023-06-01`。这是 CodeBuddy 的 Messages 协议适配，不是 Anthropic 原生模型或计费服务。

| 能力 | 转换与限制 |
| --- | --- |
| 文本、thinking、客户端工具及历史 | 保留现有转换；thinking 签名只支持本服务生成的 `cb2a_` 往返标记，并非 Anthropic 原生签名 |
| user 图片 | `source.type=base64` 转为 data URL；`source.type=url` 转为 image_url。Base64 来源支持 PNG、JPEG、GIF、WebP 的 MIME 类型；实际图片解析及远程获取由上游负责 |
| 工具结果图片 | 图片保留在对应 tool message 中，保持 tool_call_id 与内容顺序；本轮 Kimi 实测支持这一 CodeBuddy 扩展，不代表标准 OpenAI tool message 支持媒体 |
| 文本及图文 document | 支持 `source.type=text`、`media_type=text/plain`；支持 `source.type=content` 的字符串或文本／图片数组。展开为普通内容块，使用 `[文档开始]`、`[文档结束]` 保留边界，title/context 作为说明文本保留 |
| PDF、URL 文档、file_id、原生 citations | 返回 400；不下载文档、不解析 PDF、不提供 Files API。document 的 citations.enabled 仅接受 false 或省略 |
| `output_config.format` | JSON Schema 映射为 response_format.json_schema，名称固定为 anthropic_response，strict=true，schema 原样保留 |
| 工具 strict | 映射为 function.strict；不额外调整工具 input_schema |
| `thinking.clear_thinking` | 布尔值原样保留；null 按未指定处理。聊天和本地计数共用此转换，强制思考策略不覆盖历史推理保留选项 |
| `top_k`、`output_config.effort` | top_k 接受非布尔非负整数；effort 的 low/medium/high/xhigh/max 原值映射为 reasoning_effort。现有强制思考、温度策略仍优先 |
| refusal | 保留为 text 内容；拒绝文本伴随正常 stop 时，stop_reason 为 refusal。length 保持 max_tokens，工具结束保持 tool_use |
| 音频等无法转换的输出 | 非空 audio 或非文本 content 返回上游协议错误。旧 function_call、自由文本 custom 工具不转换；logprobs、annotations 等元数据不映射为原生字段 |
| beta、cache_control、未知附加字段 | 接受后忽略，不转发或记录；未知内容类型返回 400 |

JSON Schema、strict、top_k 和 effort 只保证参数转换，实际效果由上游决定。此前 Kimi 与 GLM 样本未遵守 JSON Schema；本服务不修复响应、不自动重试、不保证结构化输出。SDK 的解析辅助方法可能因上游输出不符合 schema 而失败。

图片与文档仅支持 user 消息及其 tool_result；system 仍只支持文本，assistant 支持文本、thinking 和 tool_use。工具结果必须出现在同一 user 消息的普通内容之前；空结果转换为空 tool message。`is_error=true` 添加 `[tool_error]` 文本标记，首块为图片时独立插入说明，不把图片移到额外 user 消息。

新增可选参数的 null 按未指定处理，已识别字段格式错误返回 400。非空 stop_sequences、服务端工具、原生 thinking signature 和 redacted_thinking 仍不支持。`POST /anthropic/v1/messages/count_tokens` 使用本地官方词表与模板计数；没有配置对应资源返回 404，不猜测近似模型。计数不要求 `max_tokens`，不调用上游、不计入统计；多模态内容仍不支持。详见 [分词与计数](分词与计数.md)。请求体继续使用服务的字节上限，Base64 编码后的完整 JSON 计入限制。

上游始终通过 SSE 增量读取，并只解析一次为共享中立事件；非流式聚合为 Message，流式按 Messages 状态机输出，以 message_stop 结束，不发送 `[DONE]`。正常完成必须获得上游 usage；仅 content_filter 已知可能缺失 usage，允许返回零 input_tokens/output_tokens 以避免客户端无限重试。该零值不是实际上游 token，也不会因普通 refusal 文本而扩大适用范围。拒绝原因、缓存计费和原生引用信息均不伪造。

Anthropic 命名空间中的请求校验、401/403、404、413、上游错误和未处理 500 均返回 `{"type":"error","error":{"type":"...","message":"..."},"request_id":"..."}`。request-id 响应头与信封一致，保留必要的鉴权、Cookie 清理及 Retry-After，响应使用 private, no-store。SSE 已开始后通过具名 error 事件报告异常，不伪装成功完成。

### Anthropic SDK 图片与工具结果示例

```python
import base64
import os
from pathlib import Path

from anthropic import Anthropic

client = Anthropic(
    api_key=os.environ["CODEBUDDY_API_KEY"],
    base_url="http://127.0.0.1:8001/anthropic",
)
image = {"type": "image", "source": {
    "type": "base64", "media_type": "image/png",
    "data": base64.b64encode(Path("测试图片.png").read_bytes()).decode("ascii"),
}}
messages = [{"role": "user", "content": [image, {"type": "text", "text": "描述图片。"}]}]
result = client.messages.create(model="kimi-k3-1", max_tokens=512, messages=messages)
print(result.content)

# 客户端执行工具后，将图片放入与真实工具调用 ID 对应的结果中。
# 此处构造一段示例历史；生产环境应使用上一次响应的 tool_use 块。
history = [
    {"role": "user", "content": "读取截图并描述。"},
    {"role": "assistant", "content": [
        {"type": "tool_use", "id": "call_screenshot", "name": "screenshot", "input": {}},
    ]},
    {"role": "user", "content": [
        {"type": "tool_result", "tool_use_id": "call_screenshot", "content": [image]},
    ]},
]
with client.messages.stream(
    model="kimi-k3-1", max_tokens=512, messages=history,
    tools=[{"name": "screenshot", "input_schema": {"type": "object", "properties": {}}}],
) as stream:
    for text in stream.text_stream:
        print(text, end="")
```

## OpenAI Responses 与 Codex CLI

外部入口为 `POST /openai/v1/responses`，仅接受 Bearer API Key；管理台入口为 `POST /api/admin/playground/openai/v1/responses`，仅接受会话 Cookie 且隐藏于 OpenAPI。模型发现继续复用 `/openai/v1/models`。接入配置见 [Codex 接入](Codex接入.md)。

| 能力 | 实现与边界 |
| --- | --- |
| 文本与历史 | 字符串 input、system/developer/user/assistant 消息、instructions；客户端完整回放，支持空工具结果 |
| 图片 | input_image 的 URL／data URL 与文本顺序保持；original 映射为 high；不下载图片，不支持 file_id、input_file、音频 |
| 推理 | 明文 reasoning／summary 映射为 reasoning_content；同时提供时优先 content，避免重复；不生成或接受原生加密推理 |
| 客户端工具 | function、custom、namespace、客户端 tool_search 及相应结果；校验调用 ID 与结果配对；不执行工具 |
| custom／apply_patch | 转为 `{"input":"原始自由文本"}` function 参数，完整校验后恢复；不保证或执行 grammar 约束，不做自动修复 |
| 工具顺序 | 仅缓冲连续工具组，按上游 index 输出；跨文本／推理边界保持顺序，不按元数据到达顺序排列 |
| 流式生命周期 | created、in_progress、输出项目及文本／推理／工具增量、done、completed；不发送 `[DONE]` |
| 不完整与错误 | length／content_filter 对应 response.incomplete；上游协议错误／超时对应 HTTP 错误或已开始流中的 response.failed；截断时丢弃尚未发出的连续工具组，保留已发出的输出和 incomplete 原因，不校验半截 JSON 或伪造可执行调用 |
| 非流式 | 与流式共用中立事件和状态机，上游始终增量消费 SSE |
| usage | input/output/total 来自 CodeBuddy；仅映射已观测的缓存／推理明细，完全缺失时为 null |
| 参数 | max_output_tokens、reasoning.effort、temperature、top_p、parallel_tool_calls、text.format／verbosity 映射后继续服从统一请求策略；上游是否执行格式约束见 Chat Completions 限制 |
| 无状态边界 | 只接受 store/background 为 false 或未设置；previous_response_id、conversation、context_management、prompt、自动 truncation 不支持；不实现 retrieve/delete/cancel/compact |
| 元数据 | metadata、client_metadata、include、缓存提示等未映射字段接受并忽略，不转发、不记录；拒绝不支持的工具及输入类型 |

该实现复用同一次凭证选择、共享连接、超时／取消、错误及用户隔离统计路径，不引入新的 provider 或会话数据库。客户端必须观察 Responses 终态；EOF 或 `[DONE]` 不能替代 `response.completed`。状态含义参考 [Responses 官方流式事件](https://developers.openai.com/api/reference/resources/responses/streaming-events)。

### 真实模型工具探测

实现前对 `deepseek-v4.1-flash`、`glm-5.3`、`kimi-k3-1`、`minimax-m3`、`hy4-preview` 的探测中，五者均未产生原生 custom 工具调用：HTTP 200 不代表工具能力可用。普通 function 对照均可调用；对象形式 tool_choice 被 CodeBuddy 以 400 拒绝。

同一批模型采用 JSON function 包装后，均完成原始补丁字符串的精确还原及工具结果续接。因此 Responses 对 custom 统一使用包装，不按模型猜测或自动降级。该结果仅证明测试时的工具链能力，不代表所有模型都具备视觉能力或总能生成有效工具参数；视觉验证结果沿用本文对应模型记录。

2026-09-13 使用新 Responses 请求转换、统一请求策略及共享 SSE 聚合路径复验：上述五个模型均通过 custom 补丁字符串精确还原和工具结果续接，均观测到 usage；Kimi K3.1 的 Base64 红色图片识别也通过。复验发现并覆盖了后续工具分块中的空名称／空 ID，以及结束时的空旧版 function_call 占位对象。这里的真实上游复验与固定版本 Codex CLI 的本地模拟契约是两类独立测试。
