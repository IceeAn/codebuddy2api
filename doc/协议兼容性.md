# Chat Completions 兼容性与多模态验证

本文区分网关实现保证与 CodeBuddy 上游模型能力。字段被接受、HTTP 200 或 SDK 能解析，均不能单独证明模型支持该能力。

## 接口与支持范围

外部入口为 `POST /openai/v1/chat/completions`，使用管理台生成的 Bearer API Key；管理台入口为 `POST /api/admin/playground/openai/v1/chat/completions`，仅接受会话 Cookie。两者共享转换逻辑，管理台页面仍只提供文本输入。

| 能力 | 网关行为 | 上游验证状态 |
| --- | --- | --- |
| 文本、思考、function 工具及工具历史 | 保留请求，流式输出或非流式聚合 | 已有真实验证与回归测试 |
| 图片 URL、Base64 data URL、多图、图文交错 | 保留内容块顺序、URL 和 detail；不下载、转码或保存图片 | 本次 Kimi 多图识别成功 |
| `developer`、扩展消息字段 | 保留并交给上游处理 | 不保证各模型的角色优先级 |
| 音频输入、file 内容块、file_id | 校验已知字段结构后透传；不提供 Files API | 本次端点明确拒绝 input_audio 和 file |
| 音频输出 | 请求透传；流式保留音频字段，非流式合并音频字节、转录和元数据 | 转换通过合成测试；本次上游未生成音频 |
| JSON mode、JSON Schema、strict | 原样透传 | 本次样本未遵守输出格式，不承诺约束生成 |
| refusal、annotations、logprobs | 流式保留，非流式聚合；不伪造缺失信息 | 转换有合成测试；本次 logprobs 未返回有效值 |
| 旧 function_call、custom 工具 | 保留消息；聚合参数或 input，沿用工具 ID 和上游 index | 转换有合成测试，未作真实上游承诺 |
| 未知请求字段及内容类型 | 保留给上游判断 | 不进行能力白名单拦截 |
| 未知响应字段 | 流式保留；非流式仅保证本文列出的字段 | 不猜测未知分片的合并方式 |
| `n > 1` | 本轮保留既有行为 | 非流式仅聚合首个 choice；流式可能重复其他 choice，请使用单候选 |

图片生成、视频、Responses、文件上传和已存储 completion 的查询／修改／删除不在此接口实现范围。媒体不进入统计存储；统计继续仅保存脱敏指标。默认请求体上限为 16 MiB，Base64 编码后的整个 JSON 计入限制，可由 `CODEBUDDY_MAX_REQUEST_BODY_BYTES` 调整。

## 参数及返回约定

- `max_completion_tokens` 映射为上游 `max_tokens`。两个字段均为非空时必须相同，否则返回 400；仅允许非布尔正整数，`null` 按未指定处理。上游实际截断、思考 token 和 usage 计数可能有偏差，不能视为精确额度控制。
- 原有模型默认值、命名空间剥离、强制思考和温度策略保持有效。聊天路径不查询模型能力，也不会自动换模型。
- 上游始终使用 SSE，并强制请求 usage；客户端非流式请求由网关增量聚合。内部统计始终观察原始 usage。
- 客户端仅在 `stream_options.include_usage=true` 时收到末尾 `choices: []` 的 usage 块；普通块的 usage 为 null。未启用时不发送 usage。上游缺失 usage 时不补零，异常终止不伪装为成功完成。
- 混合 reasoning/content 拆为依次到达的分块，首个 assistant 角色只补一次，合成分块不重复携带首个 choice 的 logprobs 或 usage。正常流以 `[DONE]` 结束。
- 非流式分别拼接文本、思考、拒绝、工具参数和转录；工具按 index 排序。概率和引用按到达顺序合并；usage 保留上游完整明细，不累加累计统计。音频 data 分块必须是有效 Base64，解码后的字节合并后重新编码，不拼接带 padding 的 Base64 字符串。无文本的工具／拒绝／音频响应返回 content 为 null；明确提供的空字符串保持为空字符串。
- OpenAI 命名空间中的错误统一为 `{"error":{"message":"...","type":"...","param":null,"code":null}}`。本地字段错误提供 param；保留 HTTP 状态、Retry-After 和必要鉴权头。CodeBuddy JSON 错误提取 message／msg 和 code，不将整个 JSON 错误体当作 message。内部异常不回显异常详情。

## 图片调用示例

以下使用实际模型 ID `kimi-k3-1`，不是根据模型列表自动选择的别名。图片能力仍取决于当前账号和上游模型。

```python
import base64
import os
from pathlib import Path

from openai import OpenAI

client = OpenAI(
    api_key=os.environ["CODEBUDDY_API_KEY"],
    base_url="http://127.0.0.1:8001/openai/v1",
)
image = base64.b64encode(Path("测试图片.png").read_bytes()).decode("ascii")
messages = [{"role": "user", "content": [
    {"type": "text", "text": "依次描述两张图片。"},
    {"type": "image_url", "image_url": {
        "url": "data:image/png;base64," + image, "detail": "high",
    }},
    {"type": "image_url", "image_url": {
        "url": "https://dummyimage.com/128x64/00ff00/00ff00.png", "detail": "auto",
    }},
]}]
result = client.chat.completions.create(
    model="kimi-k3-1", messages=messages, max_completion_tokens=512,
)
print(result.choices[0].message.content)

stream = client.chat.completions.create(
    model="kimi-k3-1", messages=messages, max_completion_tokens=512,
    stream=True, stream_options={"include_usage": True},
)
for part in stream:
    if part.choices:
        print(part.choices[0].delta.content or "", end="")
    if part.usage is not None:
        print(part.usage)
```
